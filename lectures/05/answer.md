- 検索だけを実行して見つかったページと、その本文で確認できたこと：
uv run python -m app.retrieval "LoRA QLoRA 違い" を実行した結果、5ページが返された。上位2件は第2回PDF p.52とp.51であり、LoRAは元の重みを固定して小さな行列A・Bを学習し、QLoRAは元の重みを4bitに量子化してメモリを節約することを確認できた。

- `--trace`で見えたツール呼び出し（ツール名・引数・回数、Treeでたどった目次など）：
・全文投入：検索ツールを使用せず、資料全文を入力した。
・ベクトル検索：search_materials({'query': 'LoRA 固定 学習 QLoRA 加える'}) を1回呼び出した。
・Tree：browse_treeを4回呼び出し、講義一覧 → 第2回 → 「選んだモデルを、いつ・どう直すか」 → PDF p.52の順に探索した。最終的に本文717文字を取得した。
・Graph：--graph --traceで実行したが、503エラーが繰り返し発生し、ツール呼び出しを確認できなかった。

- 取得した情報が足りなかった例、取得できたのに回答へ使えなかった例：
全文投入では、必要な情報が資料に含まれていたにもかかわらず、QLoRAの4bit量子化を明確に説明できなかった。ベクトル検索とTreeでは必要な根拠を取得し、正しく回答できた。GraphはAPIエラーのため評価できなかった。

- 今回の用途に採用したい方式と、その理由・比較条件の限界：
今回の質問ではベクトル検索を採用したい。必要な根拠を取得でき、正確な回答が得られたうえ、実行時間と生成API推定費用が測定できた方式の中で最も小さかった。
全文投入と検索方式では対象資料の範囲が異なり、各方式の測定も1回ずつであるため、この結果だけで方式全体の優劣は判断できない。

- 気づき・疑問：
全文投入よりも、必要なページを検索して渡す方式の方が、今回の質問では正確かつ低コストだった。Treeは正しいページに到達できたが、複数回のツール呼び出しにより時間とトークン数が増加した。Graphは503エラーのため、探索方法の効果を確認できなかった。
